## Rollback and database recovery

List private release records on msf and choose the **previous still-running** release. App-only rollback:

```sh
ssh msf '/srv/wipster/bin/release.sh rollback <YYYYMMDDTHHMMSSZ-sourceSHA-pid>'
```

This locks Wipster operations, verifies retained slot's exact image ID and readiness, atomically replaces only Wipster gateway config, validates/reloads the Wipster container, probes its release header, updates current record. It refuses a reused slot. Older images can be redeployed through the same verified CI artifact path after schema compatibility review. No global Compose down/prune or neighbor changes.

Migration failure automatically restores application route; **schema is never automatically reversed/restored**, avoiding loss of writes. Migrations must be additive/backward-compatible with retained app. PostgreSQL transactional DDL is helpful but not a blanket guarantee for every future migration. Breaking migrations require a separate reviewed maintenance plan.

Backup now (once DB exists): `ssh msf '/srv/wipster/bin/backup.sh'`. Before every future migration, an existing volume is backed up even if its DB had been stopped. Never overwrite a current DB as part of ordinary rollback.

Recovery drill uses a new isolated database: verify dump checksum; `createdb -U wipster wipster_restore_probe`; stream dump to `pg_restore -U wipster -d wipster_restore_probe --exit-on-error`; validate migrations/entities. The container smoke performs this complete restore, not just archive listing. Actual disaster recovery: close Wipster ingress with the maintenance route, stop **only** its API slots, preserve the failed volume and take a forensic backup, restore to a new Wipster volume/database, validate data and readyz, repoint only Wipster secrets/config, resume through reviewed CI. Off-host backup storage/restore has not been configured or tested; a local dump cannot protect against total host loss.
