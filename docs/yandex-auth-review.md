## Что изменено

Основной desktop вход — «Войти с Яндекс ID», без пароля Wipster и доступа к ящику. Backend принимает фиксированный HTTPS callback, выполняет Authorization Code + S256 PKCE и проверяет trusted userinfo `id`/`client_id`. Запрашивается только `login:email`; secret необязателен. Rust держит proof и полученную сессию вне React/браузера; сессия устанавливается прежним путём keyring → отдельный SQLite workspace → restart. Login/import/offline/logout/sync сохраняют прежние границы.

Новая `YandexAttempt` в additive `0005` обеспечивает multi-process callback/status/finish/cancel, TTL, однократный exchange и идемпотентную доставку того же session token при потерянном finish response. В БД хранится hash proof и hash session token. Cancel после finish отзывает только сессию этой попытки. Временный PKCE verifier очищается при callback/cancel; expired rows удаляет `cleanup_yandex_attempts`. Проверенные provider tokens не сохраняются и не пересылаются native. По официальной документации обычные токены просто отбрасываются: device revocation требует device token + secret, которые этому входу не нужны. Согласие в Яндексе остаётся до отзыва пользователем; Wipster logout отзывает собственную device session.

Identity namespace Яндекса отделён от Google; email — display metadata, совпадения не объединяют аккаунты. Привязка требует текущую точную живую device session и сохраняет Account UUID/данные; collision — 409. Старый `FOR NO KEY UPDATE` порядок account/identity сохранён через проверенный helper Google. `google_linked` теперь проверяет именно Google issuer, добавлен отдельный `yandex_linked` с serde default для прежних native metadata.
