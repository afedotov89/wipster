### P2 correction: concurrent login/link account–identity deadlock

Independent lead review reproduced a PostgreSQL cycle: ordinary Google login held identity I, then needed account A `KEY SHARE` for the deferred new-session FK at commit; explicit link held A `FOR UPDATE` and waited for I. The permanent regression was added **before** the fix and reproduced `OperationalError: deadlock detected` in **1.74 s**, with the deferred `accounts_account ... FOR KEY SHARE` query in its context. The victim can be either transaction; consuming a provider proof must not be retried to disguise this failure.

`google.live_session()` now obtains A using **`select_for_update(no_key=True)` / `FOR NO KEY UPDATE`**. Linking never changes account keys. This lock allows the normal login's FK reference to complete while still excluding sync/logout's existing `FOR UPDATE` lock. Both link phases retain the actual stored-session expiry/revocation recheck, and the second lock remains held through identity/link commit. Identity locking, unique issuer+sub, collision rejection and single-use provider exchange are unchanged. No `OperationalError` catch/retry, migration or API change was added. Lock compatibility is documented by [PostgreSQL 18](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS) and [Django 5.2](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#select-for-update).

## Independent-review corrections

The lead reproduced two P1 defects in the first submission. Both were real; passing protocol/store tests had not covered unblurred component drafts or aggregate response sizes. This revision adds permanent tests at those boundaries.

1. **Editor drafts / stale blur:** `useTaskDrafts.ts` and `useValueDraft.ts` retain a baseline per field. Equivalent object refreshes and unrelated updates preserve dirty input, while clean fields continue following authoritative values. Same-field updates retain both versions until explicit use-updated/save-my-draft. New native `save_task_draft` and `save_custom_field_draft` compare the baseline atomically under the same SQLite mutex as sync, including the race where SQLite changed before React refreshed. Clean blurs do not write. Checklist editing has stable row identities and participates in this protection, as do custom text/markdown. In-flight acknowledgements retain later typing. An open remotely deleted task keeps visible drafts instead of discarding them. Unsaved buffers remain editor-local until committed; this does not claim persistence of unblurred input across process exit.
2. **Response-size deadlocks:** push acknowledgements/receipts and conflict responses contain only `{kind,id,version}` metadata, with `batch_id` on acknowledgements. The native validates the complete frozen batch before clearing revisions. Legacy full-payload receipts are projected on read; no receipt/feed/tombstone is pruned or rewritten. HTTP uses compact UTF-8 JSON. Pull streams candidates and obeys both count and a hard **10 MiB encoded-byte** limit below the unchanged native **16 MiB** ceiling. Cursors include only emitted entries and keep `has_more` on byte splits. SQLite stages every page durably and streams latest entities within one final transaction; graph application stays atomic. Acknowledged/stale echoes return `changed=false` and do not refresh the editor or create deletion recovery records.
3. **Two actual device sessions / durable boundaries:** the native HTTP test now authenticates separate sessions for the same phone using separate one-time challenges, with a real 61-second cooldown. It reopens the client SQLite files before offline retry, after a lost push acknowledgement, and after staging only the first large feed page. It transfers 240 tasks with **24,000,000 UTF-8 comment bytes** in four legal batches (three ASCII and one Unicode-heavy), then verifies one device's logout leaves the other valid. The final run passed in **70.72 s** against PostgreSQL and two Gunicorn workers.

## Implemented path

Optional native phone account → explicit import preview/choice → separate account SQLite workspace → durable journal/outbox → authenticated PostgreSQL API → immutable feed → another native SQLite client. The original offline app remains usable and its workspace is not replaced by cloud data. Sign-in/out restart the process to isolate queued frontend and AI continuations. Offline logout disconnects locally and retries server revocation from a durable queue using credentials retained only in the OS store until acknowledged.

Architecture was documented before implementation in `cloud-sync-contract.md`. Django 5.2 LTS modular monolith, PostgreSQL production authority, account row serialization, no extra infrastructure. Raw native entity payloads are explicitly validated, versioned and scoped to an account. Optimistic conflicts require an explicit user choice; file values and captured context are projected out, not mistaken for portable attachments. Phone OTP has a Twilio Verify adapter and a deliberately enabled development provider, durable abuse limits, per-phone resend/verification locks, single-use expiring challenges and revocable device sessions.
